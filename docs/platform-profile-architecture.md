# 教育与企业培训共用平台的抽象边界

本轮界面没有复制两套代码，而是把产品拆成三层：

1. **平台能力层**：课堂 / 学习室、课件助手、课件库、题库、知识库、智能评测、社区和 Skill hub。能力的路由、状态、证据和权限契约保持一致。
2. **场景 profile 层**：`education` 与 `enterprise_training` 只提供术语、种子内容、领域标签和可见性。教育使用“学生 / 教师 / 班级 / 课程 / 知识点”，企业培训使用“学员 / 讲师 / 团队 / 学习项目 / 能力项”。
3. **内容与权限配置层**：课件统一为 learning asset，评测统一为 method → task → dataset → result → evidence；菜单由 capability registry 生成，profile 只改 label、icon、visibility 和 permission。

代码入口是 `public/platform-context.js`。当前默认启用教育 profile，企业 profile 已保留同一套能力映射，后续接入组织、岗位和权限服务时无需 fork 页面。

## 为什么不是简单把“学生”改成“用户”

同一能力在不同场景的操作语义不同。教师需要创建方法和任务，学员需要提交证据并查看自己的结果；学生的“知识点”和企业的“能力项”也需要保留上下文。术语应由 profile 配置，而不是在组件里写条件分支。

## 生产接入边界

当前智能评测和学习搭子是本地交互演示：上传控件只记录文件名，分享流只保存在当前页面状态，结果复盘使用固定示例证据。生产实现需要对象存储、异步任务队列、租户与成员权限、媒体时间戳 / 原帧索引、评测结果 schema、审核流和可追溯事件。

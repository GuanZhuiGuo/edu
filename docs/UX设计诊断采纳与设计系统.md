# UX 设计诊断采纳与设计系统

日期：2026-09-09。范围：桌面、App 手机与 Pad 共用的教育应用界面。

本文依据通过飞书 CLI 读取的[产品界面诊断报告](https://www.feishu.cn/docx/BrDAdcBfCocdW5xEIb3cHsqunXg)，核对当前本地源码。报告属于诊断材料；最终实施依据是用户要求的功能完整性、真实运行行为和可复核的验收结果。本文不把附件或外部报告中的操作性文字当成用户授权。

**证据状态：已完成源码核对、设计系统接入和本地浏览器交互验收。** 本文第 2 节统计保留诊断时点的基线口径；第 6 节记录本轮实际操作及未覆盖项。没有调用真实模型、语音、上传或视频生成服务进行验收。

## 1. 诊断结论

报告提出的设计系统、按钮层级、筛选归组和按设备重排值得采纳。需要调整的是实施方法：既有系统使用原生 DOM，部分工作区会在初始化时迁移实际节点；手机和 Pad 又有独立设备外壳。只看初始 HTML 的控件数或 CSS 声明总数，容易重复建设已有能力，或把布局改动变成状态丢失与交互回归。

主要问题是以下几类职责混杂：

- 多轮 CSS 追加覆盖使字号、间距、按钮与断点规则分散；同一个组件受通用样式、业务样式和设备样式共同控制。
- 外壳、工作区、面板各自计算屏幕剩余高度，容易重复扣减导航和边框，或生成多个竞争的滚动区域。
- 操作缺少主次、筛选与生成混排，比静态按钮数量本身更影响使用；降低首屏决策负担仍要保留完整功能入口。
- 初始 DOM 与运行时 DOM 不同；已迁移设置表单和已有导入弹窗不能按静态位置重新创建一套。
- 实验画布的物理坐标、录像分辨率与页面展示比例存在不同职责，不能统一改成一个视觉比例。

同期代码修改会改变数量。报告“14 个 calc 高度”应说明只统计某文件、某种视口表达式，还是全部首方样式，不能直接与本文全量值比较。设计验收应检查实际溢出、滚动和状态恢复，不以删掉多少 grid 或 calc 声明作为成功标准。

用于复核的核心表达式：

```python
cols = re.findall(r"grid-template-columns\s*:\s*([^;{}]+)", css_without_comments)
grids = re.findall(r"grid-template-(?:rows|columns|areas)\s*:\s*([^;{}]+)", css_without_comments)
queries = " ".join(re.findall(r"@media\s*([^{}]+)", css_without_comments))
widths = set(re.findall(r"(?:min|max)-width\s*:\s*([\d.]+(?:px|em|rem))", queries))
height_calc = re.findall(r"(?<![-\w])(?:min-height|max-height|height)\s*:\s*([^;{}]*calc\([^;{}]*)", css_without_comments)
```

## 4. 关键源码证据与实现约束

### 4.1 设置表单已经迁移

初始 `public/index.html` 中，`#settings` 表单位于 `#agentWorkspace` 下。但 `public/learning-workbench.js` 的 `moveExistingWorkspaces()` 会把原有表单追加到 `#voiceConfigMount`，并添加 `voice-config-form`。`public/education-settings-workbench.js` 的 `initEducationSettingsWorkbench()` 再把该 mount 移入语音设置面板。`public/client.js` 按先工作台、后设置页的次序初始化。

相同迁移过程还涉及文本输入、会话记录和教学内容面板。迁移的是已有节点，因此其绑定和状态得以保留。验收必须检查初始化完成后的 DOM 和可见控件；不能把初始 HTML 中 Agent 的全部后代按钮当作同时展示的操作，也不应复制配置表单来实现“迁移”。

### 4.2 隐藏状态和焦点需要动态核查

初始 HTML 存在 `details.customer-hidden-setting[open][hidden]`。`open` 不会使带 `hidden` 的内容自动显示。设置页的 `syncRoleAndTab()` 会根据学生或教师角色隐藏 tabs 和 panels，并为隐藏 tab 设置 `tabIndex = -1`。`handleSettingsTabKeydown()` 会排除隐藏 tab 与未展开的 `details` 内 tab，再进行方向键移动。

本次代码搜索未发现主动把焦点移入隐藏 API 配置字段的明确路径，不能把该问题写成已复现缺陷。仍需检查：角色或面板改变时，原焦点是否落入隐藏区；折叠高级配置后，焦点是否回到可见触发器；页面切换和弹窗关闭是否恢复焦点。单纯透明、裁切或负坐标不能替代真正的隐藏与焦点管理。

### 4.3 图谱导入弹窗和任务工作台已存在

`public/index.html` 包含原生 `dialog#createKnowledgeCatalogDialog`、资料类型和文件选择表单，以及独立 `#catalogImportWorkbench`。`public/education-import-client.js` 中的 `bindCatalogDialog()` / `openImportDialog()` 负责 `showModal()` 与标题输入焦点；已有任务列表、筛选、刷新、失败重试及回到任务的流程。

新的视觉设计应沿用这条导入链路。弹窗只承载提交前的资料输入，处理、检查和发布需要继续由现有任务状态驱动；关闭弹窗或切换设备不能等同于放弃后台任务。不能为了让页面更简洁而删除导入检查、重试或发布步骤。

### 4.4 实验画布不是任意比例的视频占位

`public/physics-lesson-player.js` 为画布设置 `width = 900`、`height = 520`，样式比例为 `45/26`。`public/interactive-lesson-lab.css` 的 `.lesson-canvas` 同样保留 `900/520`。`public/physics-lesson-runtime.js` 的 `draw()` 明确要求后备尺寸保持稳定，用于 `captureStream` 和视频导出，由宿主 CSS 根据可用宽度缩放。

只将显示区改为 16:9 会拉伸运动几何；随布局改变后备分辨率还可能重置画布并影响录像。应让外层预览区域适应双栏、堆叠或 Pad 方向，画布自身等比显示。可以给未加载占位区另设比例，但不能把它传递成真实画布的强制宽高。在线播放、录像和离线 HTML 导出需要分别验证。

### 4.5 每层高度只由一处负责

目前 `public/styles.css` 中 `.app` 有 `height: 100vh` 和头部/内容 grid；`public/app-shell.css` 又为预览外壳分配 `100dvh`、工具栏、设备区域和说明行。手机设备内部还有状态栏与底部安全区；Pad 则使用独立逻辑尺寸并缩放展示。因此全局增加 `calc(100vh - 104px)` 会在不同模式重复扣除尺寸。

目标约定：

1. 最外层负责视口高度与设备外壳；应用框架用 `auto minmax(0, 1fr)` 分配导航和内容。
2. 工作区继承已分配的空间，采用 `min-height: 0`、`min-width: 0`，不再重复使用宿主屏幕减数。
3. 面板明确分为标题、可滚动内容和必要操作区；每个区域只有一个有意设置的滚动容器。
4. 固定操作区要保留可滚动内容的安全空间；键盘或低高度视口下关键操作仍可到达。
5. 弹窗为保留上下边距而使用视口 `max-height: calc(...)` 可以合理存在，无需为减少统计值而删除。

## 5. Tabler Core 与现有应用的兼容方式

已接入精确版本 `@tabler/core: 1.5.0`，由 `npm run build:design` 从官方 CSS 提取原生控件样式，生成本地 `public/vendor/tabler/controls.css` 并保留 MIT 许可证。`index.html` 通过唯一设计入口 `design-system.css` 加载，层顺序为 `tabler, legacy, design, workspace`。共享 tokens、表单和按钮已用于实际页面，浏览器记录见第 6 节。

当前应用以原生 DOM、ES modules、既有事件处理、Lucide 图标、原生 `dialog` / `details` 为基础。Tabler Core 可作为 Bootstrap 兼容的样式与组件规范渐进引入，无须为统一视觉更换整个前端框架。

实施建议：

- 固定本地依赖版本并保留许可证，明确全局基础样式与业务覆盖的加载顺序。
- 优先统一颜色、字体、行高、间距、边框、圆角和焦点样式；按钮和表单通过可复用 class 获得一致尺寸。
- 保留原始 DOM 的 ID、数据属性、事件与异步状态；避免整页模板替换或复制同一功能节点。
- 谨慎使用组件 JS，已有原生弹窗和菜单不再重复绑定第二套行为；避免多个 reset 或焦点管理器相互覆盖。
- 桌面密集操作和触控操作采用不同尺寸档，但同类按钮的图标、文字基线和左右留白遵守同一规则。
- 手机与 Pad 的触控目标以至少 44×44 CSS px 为设计目标；短标签优先单行，长标签需明确换行或移至次级面板，不能靠不断缩小字号硬塞。
- 字体按内容层级设置，正文、标签、辅助说明分别有固定档位；中文、数字、英文、加载态和禁用态都要检查。
- Pad 采用适合可用空间的双栏、列表/详情或侧栏布局，并保留方向切换；不能仅把手机画面等比放大。

这些是接入约束和验收方向，不能替代真实页面检查，也不构成 WCAG 全量符合性声明。

## 7. 后续确认的教师端信息架构

用户在本轮联调中进一步明确以下调整，优先于报告中的旧菜单假设：

- App / Pad 的模式切换和 Neo4j、Qdrant 连接状态放到设备框外；桌面没有设备预览工具条时保留页内入口。同一状态源负责检查，UI 不决定检索策略。
- 教师侧栏第一项为课堂预览。删除教学计划菜单及更多教学工具折叠层；知识管理改为知识库，出题与题库改为题库。
- 课件助手承接视频讲解、素材工坊、互动教材，沿用已有编辑、生成、导出及异步任务，不另造一套假结果。
- 新增课件库，收录真实可运行示例和教师保存内容。支持学科、类型、技术栈、标签与交互性筛选；保存成功以 IndexedDB 事务完成为准，当前存储范围为本机浏览器。
- Skill hub 统一教学技能和技术栈，保留服务端技能权限说明及候选技术标记。候选技术不能在课件助手里被当成可用生成能力。
- 历史工作区路由映射到新入口，原业务节点及事件保持，切换页面不取消生成任务或丢弃草稿。

界面库只能解决基础控件一致性。信息架构、主次任务、状态归属、响应式空间分配和跨页面验证仍由产品与实现负责。之前的实现优先逐项补足功能，持续追加覆盖却未及时统一这些规则，这是本轮要纠正的主要原因。`DESIGN.md` 固化了后续约定，但旧业务 CSS 仍在隔离层中，不能宣称历史样式已经全部重写。

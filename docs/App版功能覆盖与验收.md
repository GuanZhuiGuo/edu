# 手机、Pad 显示模式功能覆盖与验收

更新时间：2026-09-09。对象：AI教师当前 Web 系统的手机、Pad 与桌面显示模式。

本文依据当前源码盘点功能入口与验收要求。22 个入口均已通过浏览器可达性与手机屏幕边界检查；子功能按实际执行范围单独记录。未运行真实上游模型、语音、批改或生成任务时，不得将入口可点击、表单可填或本地状态反馈表述为真实业务完成。

## 目标与实现边界

当前系统右上角提供设备菜单，可选择「桌面版」「手机版」「Pad 版」。App 模式参考用户提供的手机截图，采用圆角黑色手机外壳、系统状态栏、手机屏幕和底部手势条；屏幕内使用适合手机的字号、触控区域、卡片、底部导航及弹层。参考图只定义外壳和 App 交互风格，不把参考图中的家长中心、学习报告示例数据追加为本系统已有业务。

宿主页面持有一个持续挂载的同源 iframe。桌面版、手机版和 Pad 版通过调整该 iframe 的视口与显示模式切换，复用同一个应用 DOM、运行时、事件绑定与服务端接口，不另建简化功能副本。切换时不重新设置 iframe 地址，不重新启动应用；当前角色、账号、页面、未发送文字、已选择图片、未保存表单、对话和音频状态均应保持。刷新后的恢复能力以原系统存储逻辑为准，不把仅在当前运行时保留的草稿承诺为跨刷新持久化。

学生端包含 8 个功能入口，底部导航提供 AI教师、课程、计划、练习、更多；更多提供剩余学习功能与教师端切换。教师端包含 14 个功能入口，底部导航提供总览、学情、课程、题库、更多；全部教师工具通过更多菜单访问。页面间返回与原有书架、详情、弹窗返回机制均应可用。

这是现有 Web 系统的 App 风格显示模式，不包含原生安装包、应用商店发布或新增原生系统权限。麦克风、摄像头、播放、下载和录制仍由浏览器能力、用户授权及原系统上游配置决定。

## 本轮新增与调整

- 手机：标题 20px、分区 17px、正文 15px、按钮 14px、辅助文字与底栏 12px；常用操作 44–48px，图标和文字对齐，长内容按钮按内容撑高。课程、日历、题库、学习搭子、教师工作台逐页处理；知识书架改为完整封面横向浏览。
- Pad：横屏外壳 1064×798、竖屏 798×1064，实际内容视口 1044×728 / 778×994；按宿主窗口等比缩放。保留侧栏与全部角色入口，横屏按列表/详情和工作区分栏，竖屏重新安排列宽与内容流。独立的横竖屏控制不重载应用。
- 连接：右上角呈现真实服务端连接状态，点击查看 Neo4j、Qdrant 与重新检查；手机用可访问的状态指示点节省空间。请求失败显示状态未知，Qdrant 缺集合显示“索引未就绪”。后台约30秒恢复探测，故障时跳过远端联合检索，继续读取已审核本地知识。
- 参考附件 `课堂内外AI原型源码.tar.gz` 的字号层次、按钮继承字体与图文对齐方式；没有执行附件脚本或把附件中的示例业务数据引入系统。

## 真实能力与空态保留

App 模式复用当前系统的服务端和前端能力，不补造新的数据库、模型结果或学习记录。课程管理数据库、教学计划和部分班级聚合尚未接入时，保留当前的未接入/无数据说明；原有待审题、种子题、演示账号、教师预览、配置缺失与错误反馈继续显示。

「上传控件可用」只证明可选文件，「生成按钮可用」只证明能触发原有流程。模型回复、真实语音、图片批改、资料解析、分镜生成、视频合成、审核发布以及持久化写入，只有取得各自的权威结果并记录测试条件，才能单独标记业务验收通过。此次外壳和手机界面验收不默认覆盖这些真实上游链路。

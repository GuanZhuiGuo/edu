# 课件分类与创作架构研究

## 决策结论

课件库采用多维筛选：**资源形态、学科、学段、知识主题、呈现方式、交互方式、制作技术与关键词**分别表达不同属性。默认界面只突出资源形态、学科主题树、关键词和学段；其他条件渐进展开。教师查找资源时从教学内容出发，技术目录从可实现的呈现效果与能力职责出发；两者通过知识主题和能力标识关联，不共用一棵包罗所有属性的大树。

资源形态确定为三个主类：**知识点资源、整套课件、视频讲解**。“知识点资源”比“知识点卡片”更准确，能涵盖卡片、函数图、几何图解、参数实验与知识导图。二次函数、酸碱滴定等具体名称作为知识点词和标签，不再与整套课件、视频并列。高中与大学是适用学段；二维与三维是呈现方式，都不进入知识主题树。

制作入口以自然语言描述目标为主，少量选择用于补齐影响结果的条件。当前界面已把工具选择折叠为可选项，仍使用已有的关键词建议与生成链路。自然语音、多轮自主创作与 Deep Agent 后台属于下一阶段方案，本次没有实施。

后台编排的优先研究候选是 **LangChain Deep Agents JS**。原因是与当前 Node/ESM 后端匹配，并提供规划、工作文件、上下文与子任务接口；这一判断不等于它的中文教学质量或成本已经优于当前 Pi。应先统一任务、产物和版本契约，再以同一组领域工具比较两种编排路线，保留 Pi 处理短任务及回退。[^r10]

## 教育需求与技术供给

### 教师需要找什么

课件分类的首要目标是降低备课成本。教师通常已经知道面向什么学生、要解释什么、课堂上要怎样使用；他们不一定知道哪个 JavaScript 引擎适合这个目标。把“函数”“视频”“三维”“高中数学”“OpenMAIC”放在同一个下拉菜单里，会让教师同时判断内容、受众、载体和技术实现，选中一项还会错误排斥其他本来可以共存的属性。

以下是基于教学任务的产品分析，尚未通过本项目教师访谈或使用数据验证。它用于确定信息架构的初始假设，后续应通过查找成功率、预览后使用率与修改成本评估，而非仅看生成次数。

| 备课任务 | 最先需要的信息 | 合适的入口 | 选型重点 |
| --- | --- | --- | --- |
| 明天解释一个难点 | 学科、主题、学生学段、目标概念 | 主题树与关键词 | 正确性、理解门槛、准备时间 |
| 让学生发现变量关系 | 可调参数、可观察量、活动任务 | 知识点资源＋交互条件 | 受控模型、即时反馈、参数边界 |
| 准备一节完整课堂 | 学习目标、环节、顺序、练习与总结 | 整套课件 | 内容完整性、节奏、可编辑结构 |
| 布置课前或课后观看 | 主题、时长、字幕、终端兼容性 | 视频讲解 | 连续播放、讲解准确、可访问性 |
| 修改已有资源 | 目标版本、可修改部分、来源 | 预览后“复用” | 保留原件、修改范围、再次保存 |

从供给角度看，同一教学目标有多种实现路径，成本与可控程度差别很大。函数关系可以用精确曲线与参数滑杆表达，也可以拍成线性视频；后者更适合讲故事，前者更适合控制变量。三维对于空间结构可能有帮助，但不会自动使代数概念更清楚。选择应依据教学目标与可用表达能力，而非使用最新、最复杂的引擎。

### 可以借鉴的标准与产品

LRMI 将 `learningResourceType`、`educationalLevel`、`interactivityType`、`educationalAlignment` 分为不同属性。它支持“资源是什么”“适合谁”“怎样学习”“对齐什么框架”分别建模，但没有规定本项目必须使用哪三个资源形态。[^r1] CASE 的知识/能力节点具有稳定标识和父子关系；其信息模型把学段作为独立且可多值的属性，为主题树和学段分离提供了直接依据。[^r2]

产品证据也支持这种分工。H5P 同时存在 Interactive Book、Course Presentation、Interactive Video 和 Flashcards，说明组合资源、视频与细粒度活动可以并存；视频也可能带交互。[^r3] GeoGebra 的资料卡区分 Activity 与 Book，同时提供函数、几何等主题入口；PhET 分别设置 Subject、Grade Level 和 Compatibility。[^r4][^r5] 这些是可借鉴的组织方式，不是对本地枚举或教学效果的认证。

本研究以中小学备课为主要使用场景，保留大学与职业教育的扩展。技术和框架事实核对到 2026-09-12；推荐学段属于编辑判断，不等于教材版本或课程标准已完成对齐。

## 课件库分类模型

### 资源形态只回答交付物是什么

| 枚举 | 显示名称 | 判断标准 | 不应混入的内容 |
| --- | --- | --- | --- |
| `knowledge_resource` | 知识点资源 | 围绕一个或少量关联目标的可复用单元，如概念卡、动态图解、实验、导图 | 不能因内部使用某个框架就升级为整套课件 |
| `lesson_package` | 整套课件 | 作者确认的成套教学结构，具有可保存的环节顺序、资源关系和必要内容 | 单张截图、一个 HTML 页面或当前场景快照不能自动认定为完整套件 |
| `explainer_video` | 视频讲解 | 以可播放视频为主要交付物，具有可用视频资产 | 不等同于某个视频模型，也不保证具有可编辑工程 |

一套完整课件可以包含知识卡、互动实验和视频。顶层条目仍按主要交付形态归为整套课件，内部资源未来可以通过父子关系单独复用。不能因为包含视频就同时复制成多个相互独立、内容不一致的条目；视频若单独入库，应成为有明确来源关联的独立资产。

视频的生成机制是制作信息。视频模型生成、PPT 配音合成、程序化数学动画、交互画布录屏，最终都可能交付 MP4/WebM，但它们的可控性、编辑能力和费用完全不同。当前不应把“视频讲解”专门等同于某个模型：视频模型是执行能力，成片是资源形态。PPT 内容解析、镜头生成、字幕配音和合成也需要分别完成，不能用“PPT 转视频”一个标签掩盖缺失步骤。

### 学科、学段与知识主题

学科是稳定入口，当前词表包括语文、数学、英语、物理、化学、生物、历史、地理、道德与法治、科学、信息科技、艺术、体育、综合。资源允许多学科；旧数据中确实存在的其他学科不会被静默删掉。这里列出的是目录可表达的范围，不代表每个学科已有可用内容。

学段独立为小学、初中、高中、大学、职业教育。一个函数资源可以跨初高中适用，大学资源也可能包含高中先修内容，因此数据应允许多值。没有可靠信息时显示“未标注”，不能让模型或标题关键词自动制造学段事实。

| 学科示例 | 一级知识主题 | 更细内容的放置方式 |
| --- | --- | --- |
| 语文 | 阅读理解、写作表达、语言积累 | 修辞、议论文、古诗鉴赏等使用知识点词或后续子节点 |
| 数学 | 数与运算、代数与方程、函数、几何、统计与概率 | 二次函数、圆锥曲线、勾股定理等使用知识点词 |
| 物理 | 力与运动、电与磁、光与波、热与能量 | 斜面、碰撞、电路、透镜等使用知识点词 |
| 化学 | 物质与结构、化学反应、实验方法 | 酸碱滴定、分离提纯等可以跨主题标注 |
| 生物 | 生命与结构、生态与环境 | 细胞器、遗传、食物链等使用知识点词 |
| 地理 | 自然地理、人文地理 | 地形、气候、人口与产业等使用知识点词 |

这是一套适合当前规模的发现词表，不是严密完备的学科本体。大学内容规模增长后，可增设微积分、线性代数、离散数学、近代物理等稳定主题节点；不要把它们全部勉强塞进现有五个数学主题，也不要现在为没有资源的每门大学课程创建深层目录。课程、教材版本、年级、章节属于另一条教学使用路径，未来可以映射到同一个知识主题，不能混成同义层级。

当前实现为“学科→主题”两层导航，以 `math/functions`、`physics/mechanics` 等稳定 ID 表达主题。过滤逻辑已支持按路径段匹配后代，例如函数主题可以匹配未来的二次函数子节点；它不是 CASE 完整关系服务，也没有把本地 ID 冒充外部课程标准 GUID。[^r2]

### 呈现、交互与关键词

| 维度 | 当前词表 | 使用原则 |
| --- | --- | --- |
| 呈现方式 | 图文、二维、三维、音频、视频 | 可多值；描述实际产物，不从引擎理论能力推断 |
| 交互方式 | 阅读观看、调节参数、交互探索、练习作答 | 可多值；翻卡不等于作答，滑杆不等于有学习记录 |
| 制作技术 | SVG、Canvas 2D、Matter.js、Planck.js 等已有标识 | 进入更多筛选和详情；保留实际运行依据 |
| 知识点词与标签 | 二次函数、摩擦、酸碱、复习等 | 补足精细检索，不无限增加顶层枚举 |

“二维”通常只说明画面所表达的空间维度，“交互探索”才说明教师或学生能做什么。视频也可能叠加作答，但只有实现了相关控件与状态才应标注。类似地，一个 Three.js 查看器支持三维浏览，不代表它会解物理方程或能从任意文字生成三维模型。[^r6]

关键词索引覆盖标题、描述、学科、主题名称、学段、呈现与交互名称、技术和标签；当前按空白分词，词与词之间为 AND。不同筛选维度为 AND，同维多值为 OR。例如“物理＋初中＋二维”是交集；选择“摩擦或周期”两个知识标签是并集，再与前面的条件相交。这是确定性文本筛选，不需要为每次查询调用模型、Neo4j 或 Qdrant。

标签应区分受控标签和自由词：主题 ID、学科、学段由目录管理；资源作者可补具体知识点和使用场景。规模扩大时再引入同义词表，如“力学↔力与运动”“2D↔二维”，并保留作者原词。自动标签应可校正并标明来源，不能成为未经核对的课程标准对齐事实。本次没有实现自由标签编辑器或自动语义标注服务。

## 查询与制作的两条路径

### 查找时逐步缩小范围

桌面端使用左侧学科主题树，顶部资源形态切换，右侧关键词、学段与结果。手机端折叠主题树和高级条件，优先显示搜索及可预览资源。Pad 按内容区域宽度决定卡片列数，避免设备宽度足够、但扣除两层导航后仍强行塞入三列窄卡片。

已选条件显示为可移除项，清除全部后焦点回到关键词输入框。主题数量由真实当前数据计算；无结果时可以减少条件或前往制作。整套课件的空态明确说明完整结构保存尚未接入，避免让空分类误导教师反复生成，却仍无法保存到对应类别。

### 制作时描述目标

制作不需要复制课件库的全部筛选器。一个可执行需求通常需要学生对象、知识目标、期望课堂活动及交付约束，例如：“给八年级学生做一个斜面摩擦实验，让他们调倾角比较运动，再回答一道迁移题。”技术选择可以在后台完成；若要求离线播放或必须交付视频，这种约束才值得优先澄清。

本次已把“指定制作工具”折叠在“制作选项（可选）”中，保持所有既有入口可达。提示写明“关键词建议”，与实际实现一致。目前没有自然语言语义规划、自主组合多种技术或教师语音创作能力；例如选择 OpenMAIC 仍需要使用现有工具入口，不能把关键词匹配包装成 Deep Agent。

下一阶段才引入“描述目标→回显理解→自主制作→对话内预览→继续修改→保存版本”。当两种载体确有取舍，可以给出两份有实质区别的候选；常规需求不必总生成三个版本。教师可以说“保留第一版，文字更短”，但系统必须绑定明确产物 ID 与版本，不能只靠对话文本猜“第一版”指什么。

## 技术目录的专业组织

### 技术具有多种职责

技术页采用四组独立筛选：教学效果、能力职责、适用学科、知识主题，另设接入状态。“教学效果”在这里指画面和操作形式，不指经过实验验证的学习增益。

| 维度 | 分组 | 示例 |
| --- | --- | --- |
| 教学效果 | 二维图解、三维空间、图表与数据、结构化文档、音视频、基础能力 | Three.js→三维空间；ECharts→图表；OpenMAIC→结构化课堂内容 |
| 能力职责 | 生成、编排、渲染、仿真、编辑、校验、导出 | Matter.js→仿真；KaTeX→公式渲染；FFmpeg→编辑与导出 |
| 学科与主题 | 多值标签，通用能力可跨学科 | KaTeX 服务数学/物理/化学；细胞适配主要服务生物 |
| 接入状态 | 已接入、源码已纳入、待接入 | 拥有依赖源码不等于教师界面已可调用 |

课件库里的某份资源只标自身实际能力；技术目录可以描述一个工具经过核对的供给能力。它们共享词表的语义，但不会相互推导“已有引擎，所以所有课件都可交互”。对教师显示课堂效果与适用边界，技术名称、许可和调用依据放入可展开详情。

### 本项目的供给收敛

当前技术目录共 46 项，默认展开 16 项已接入教学能力，26 项备选方案与 4 项已接入基础能力折叠。这里“已接入”意味着有当前主应用调用链与实现依据，不代表模型、浏览器或服务此刻必然可用。搜索或选择候选状态时，备选仍可被找到；正常浏览不会把未接入工具和当前能力混成同一张平铺清单。

| 任务 | 当前优先供给 | 备选或能力边界 |
| --- | --- | --- |
| 受控函数与平面几何 | Canvas 2D、SVG 预设 | JSXGraph/GeoGebra 的几何约束与编辑能力不能被少量预设完整替代 |
| 二维力学实验 | Matter.js、Planck.js | 两者均有真实调用与切换，保留；未覆盖任意物理实验 |
| 空间与细胞观察 | Three.js、Cell Studio 适配 | 当前是查看器与受限细胞数据，不是通用文字转三维 |
| 数据、知识关系、公式 | ECharts、G6、KaTeX | 图表、关系布局和排版均不负责证明教学结论正确 |
| 成套内容组织 | OpenMAIC、DeepTutor 官方生成桥 | 主应用只接入特定管线；完整成套保存仍是后续工作 |
| 镜头图像与视频生成 | Seedream、Seedance 的方舟客户端 | 需要凭证、模型配置与上游可用；本次仅验证本地调用链 |
| 视频合成与录屏 | FFmpeg、MediaRecorder | 媒体处理不替代视频模型、分镜设计或数学动画引擎 |
| 新数学动画、复杂编辑 | Manim、Remotion、其他备选 | 接入、输出契约、运行环境与许可条件须单独验证 |

没有足够证据支持“完全可替代且不优秀”的一刀切删除。当前的有效收敛是去除默认目录中的候选噪声、确立主路径，并不增加重复引擎。例如已有 Three.js 就暂不再增加 Babylon.js，已有 ECharts/G6 就不为普通图表额外增加 D3/Plotly；这属于本项目成本判断，不是公开项目的全面优劣排名。[^r6][^r7]

需要保留职责差异。FFmpeg 负责合成转码，Manim 负责数学对象动画，二者不等价；KaTeX 排公式，MathLive 编辑公式，也不等价。BlockNote 建立在 Tiptap/ProseMirror 之上，却提供不同层次的编辑体验，不能仅凭共同依赖就判定任意一个可以无成本替代另一个。[^r8]

真正淘汰一项技术，应同时满足：主应用没有运行依赖；已选技术完整覆盖被推荐的需求；交互、正确性、导出、维护成本和许可不存在必须保留的差别。如果满足这些条件，再删除其默认推荐与适配代码，并用真实课件回归验证。仅比较 star 数、截图漂亮程度或“都能做 2D”不足以支持删除。

许可也会改变供给选择。GeoGebra 的应用与素材有商业使用边界；Remotion 并非通用 MIT 许可；FFmpeg 的具体义务受构建和所带组件影响。目录记录实际来源和范围，正式集成再针对最终分发对象核查，不能用一个 GitHub 仓库的许可证代替其全部素材与服务条款。[^r9]

| 项目 | 本次结果 | 保留边界 |
| --- | --- | --- |
| 分类数据 | 新增 catalog v2，资源形态/学科/学段/主题/呈现/交互分离 | 旧 type 仍负责渲染器分派 |

| 课件库 UI | 主题树、三形态入口、关键词、学段、更多筛选与标签 | 未增加云同步、资产版本库或完整课件保存 |

| 技术页 | 46 项多维目录、默认能力与备选分组、接入状态纠偏 | 无依赖卸载、无新执行器接入 |
| Deep Agent | 独立比较与架构方案 | 未安装候选框架、未修改执行架构 |

数据升级采用兼容视图：读取 IndexedDB 后生成新的 catalog 对象，不触发写事务；正常保存时才记录新版字段。原 `lesson`、几何模型、HTML、视频地址、未知扩展字段都保留。作者已有明确元数据优先，显式空数组保持为空。新内置样例的推荐学段不会覆盖以前保存的用户内容。

定向回归共 **51 项通过**，覆盖分类/组合筛选、旧存储零写入、完整 payload 保留、保存与事务失败、几何与 Lesson DSL、助手导航与技术分组。浏览器检查覆盖手机、Pad 和桌面上的相关入口、主题筛选、三维筛选、空态与焦点回归；它是本地界面验收，不是新增模型能力或上游生成效果验证。

后续最应补齐的是成套资产契约与版本保存，其次是长任务的持久状态，再开展 Deep Agents JS 对照试点。不能先把“整套课件”打上标签，再假定保存后的静态画面具有原来的互动、场景顺序和课堂逻辑。

## 原因反思与持续治理

当前问题的根因是“按开发接入顺序增加产品入口”：新做一个实验就增加一种 type，新接一个引擎就增加一个筛选值，新增加一种展示又进入同一个菜单。内部渲染契约逐渐变成教师的分类语言，产品分类因技术实现变化而变化。

统一 UI 库可以修复按钮、字体、间距、选择器和焦点规则，但无法决定“视频”和“力学”是否同级。当前已经采用 Tabler 与共享设计 tokens，本轮没有为分类问题再换整套 UI 库；需要建立的是独立于组件库的领域词表、资源契约和能力目录。

治理上应分别维护三件事：资源目录说明资产是什么，知识目录说明内容教什么，能力注册表说明系统能怎样制作与运行。新增技术先补能力及验证依据，新增课程内容先补知识主题与关键词，只有交付形态发生稳定变化才调整主枚举。这样更换渲染器或 Agent 框架时，教师的课件分类仍能保持稳定。

未来评估分类是否成功，应观察“找到可用资源”而非“点了多少筛选”：给教师一组真实备课任务，记录查找时间、找不到的词、预览后使用率、错误分类率与修改后保存成功率。大学主题扩展、教材章节导航或更多枚举都应由这些证据驱动。现有报告没有教师访谈、生产使用数据或学习效果实验，因此不对教学增益与节省时间做数值承诺。

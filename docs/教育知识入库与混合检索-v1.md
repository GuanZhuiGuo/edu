# 教育知识入库与混合检索 v1

## 目标

把已人工审核的 `DocumentIR + CandidatePack` 发布为同一个版本的两种数据：

- Qdrant：原文片段、知识单元、题目的 dense + sparse 向量。
- Neo4j：文档、修订、片段、知识单元、题目和已审核的类型关系。

学生作答、标准答案、私有解析和掌握度证据不进入这个共享知识索引。

## 发布流程

```text
verified import
  -> publication plan + manifest
  -> Neo4j release=preparing
  -> Ark dense embedding
  -> Ark sparse（如实际返回）或 lexical_sparse_v1
  -> Qdrant staging points
  -> Neo4j graph + release=ready
  -> Qdrant points=published
  -> Neo4j 原子切换 ACTIVE_RELEASE
```

Qdrant 和 Neo4j 之间不伪造分布式事务。只有 Neo4j 中被标记为
`ACTIVE_RELEASE` 的 release 可以被检索；中途失败的 Qdrant 点或图节点保持
不可见，不会污染当前线上版本。

## 检索流程

```text
server identity + corpus
  -> Neo4j 解析 ACTIVE_RELEASE
  -> query dense embedding
  -> query sparse embedding / lexical_sparse_v1
  -> Qdrant dense + sparse RRF
  -> tenant/corpus/release/ACL 结果二次校验
  -> 以 top knowledge IDs 做 Neo4j 同 release 一跳扩展
  -> 返回带 source_anchor 的检索回执
```

浏览器不能传入 `tenant_id`、`principal_id` 或 `release_id`。这些值由服务端会话与
Neo4j 发布控制面决定。

## HTTP 接口

- `GET /api/education/knowledge/config`：查看模型、向量库、图库是否已配置。
- `GET /api/education/knowledge/health`：检查 Qdrant 与 Neo4j 连通性。
- `POST /api/education/imports/:jobId/publish`：发布已审核导入。
- `POST /api/education/retrieval/search`：对 active release 做混合检索。
- `GET /api/education/knowledge/active-release`：查看指定 corpus 当前激活版本。

`/api/education/knowledge/search` 是原 MVP 的本地教学卡检索接口，v1 中保留；新的
发布知识库使用 `/api/education/retrieval/search`，避免破坏现有对话 UI。

## 本地运行

请参考 `infra/education-knowledge/README.md` 启动固定版本的 Qdrant 和 Neo4j。
配置本地 `.env` 后，执行：

```bash
npm run smoke:knowledge
```

该命令使用隔离的 smoke corpus 和 deterministic 向量，用于证明双库真实写入、
release 激活和 RRF 查询链路；它不代表 Ark 正式 embedding 质量。正式集合
`education_knowledge_v1` 会在第一个真实 Ark embedding 返回后按其向量维度创建。
